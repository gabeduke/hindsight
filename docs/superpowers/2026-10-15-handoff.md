## What changed since the last handoff

**Play mode makes sound.** Spec: `specs/2026-10-14-play-mode-sound-design.md`.

- A trick is a **read head** that leaves the transport while a pad is held.
  The transport keeps counting underneath, so a release is back in time with
  nothing resynchronised. The MIDI clock out, catches and punches never see a
  trick.
- The pads:

  | Pad | Sound |
  |---|---|
  | BREAK | Silence |
  | STOP | Winds down over a beat |
  | REV | Backwards |
  | CHOP | The last slice, its length from the quantise switch |
  | ½× / 2× | Varispeed |
  | 1–4 | Drop that track out |

- How a press travels:
  - The page sends each press and release over `GET /api/tapes/play` the
    moment it happens, and the Pi quantises it on its render head.
  - The Pi reports its **lead**, how long a press takes to be heard. It
    measures 225 ms on the main rig.
  - The page draws the lead as the gap between a pad going dim and going
    bright.
- Code:
  - `internal/tape/trick.go` and `internal/api/play.go`;
  - `web/static/lib/play/link.js`, with `clock.js` for the grid and the ring.
- An independent review found six defects in the engine before merge, all
  fixed with failing-first tests. The worst was a tick at every loop seam on
  loop-filling clips.
- **A jam is already recorded.** The tape's output comes back through the
  Sidekick's MAIN, so tricks played are in the ring and save as a take like
  anything else.

**The object library is finished** (#98). These now live in `lib/objects/`:
- the VU meter, reels, reel window, cassette, ribbon, LCD, grease pencil,
  pennant and icons;
- the label as materials, with no module.

The transport keys were left out: they are the app's buttons, styled by
tokens that follow the scheme. The bench at `/objects.html` has a size slider
and a PNG still.

**Releases are now an allow-list** (#97). Only `cmd/`, `internal/`, `web/`,
`deploy/` (less the hub's manifests), `go.mod`/`go.sum` and `docs/guide.md`
cut one. Docs like this note don't.

## Next: build the rooms

**Everything, off `main`.**
- Every spec gets built (2026-10-15). Nothing goes to `main`, so nothing
  cuts a release.
- Gabe validates in the morning, deploying a branch to the Pi himself with
  the deploy script.
- Steps that aren't right yet are left off; the rest merge.

That is why the branches are a **tree that follows the dependencies**, not
one stack. A leaf can be dropped without touching its siblings.

```
claude/play-style-recording-redesign-f37e80   the specs, PR #104
├─ rooms/r1-scene                 R1, no visible change
└─ rooms/p1-two-rooms             P1
   ├─ rooms/p2-buffer             P2
   │  └─ rooms/p3-strip           P3: the verbs need P2's buffer
   │     └─ rooms/p4-fx           P4: the pads live on P3's strip
   ├─ rooms/p5-listening-room     P5
   └─ rooms/p6-rig                P6
rooms/all                         every finished branch merged, to try together
```

- **Each branch has a PR against its parent,** never against `main`. Each
  body says: *retarget to main before merging*.
- **`rooms/all`** merges every finished branch, resolving the conflicts that
  are bound to come (each branch bumps `CACHE` in `sw.js`; `rooms/all` takes
  one bump above them all). It's the one branch to deploy to try everything
  at once.
- **Then the render briefs,** only once all of the above is built and
  checked, each a leaf off what it needs:
  - R2 (shelf to deck), R3 (the room in 2.5D) and R7 (the lathe), off P5
    with R1 merged in;
  - R4 (cables), off P6 with R1.

  **R5 (device models) and R6 (three.js) wait for Gabe.** A model is judged
  by eye, and vendoring three.js is a size decision.

**Run it locally,** on the Mac: it needs Go, the demo and Playwright. The
sandbox lesson (Play mode, 2026-10-14) was that UI built where it can't be
rendered merges broken. Independent branches can be built in parallel, each
in its own worktree with its own demo port. R1 and the P4 engine don't wait
for P1.

## How the sound was checked, for whoever changes it next

There's no ear in a sandbox, so:
- `trick_test.go` reads a ramp-signal tape, so every output value says where
  the head read. It includes:
  - continuity checks (the biggest step between two frames);
  - a loop-filling clip played through its seam;
  - a 300-trial random jam;
  - a two-engine test that a jam leaves the tape sample-identical once let go.
- End to end:
  1. Put the demo's output in `both` (`PUT /api/tapes/output`).
  2. Record `/api/tapes/stream` (stamped PCM16 packets) while a script holds
     pads on `/api/tapes/play`.
  3. Read the level per 50 ms. BREAK reads 0 on its sixteenth, and STOP
     falls to 0 over a beat.
- `BenchmarkRenderABlock` is the CPU number to re-run on a Pi: one 21 ms block
  with four tracks, plain and under each trick.
