## What was built today

Two spec-led threads, both from specs merged this morning:

- **The object library** (`2026-10-14-object-library-design.md`). Physical
  objects each have a module in `web/static/lib/objects/` — VU meter, reels,
  reel window, cassette, ribbon. Materials are cut out into `objects.css`.
  `motion.js` holds shared physics (the real VU ballistics, reel inertia, one
  shared ticker). `/objects.html` is the bench: every object, every state, on
  one screen.
- **Play mode** (`2026-10-14-play-mode-design.md`). A performance surface in
  `web/static/lib/play/`, behind a per-device flag. Momentary pads quantised
  to the tape's grid, one event bus under touch and the PC keyboard, and the
  arm → fire gap drawn so a player can lead the beat.

## The next step, and why it needs this machine

**Play mode makes no sound.** The pads arm, fire and light; nothing is
audible. Wiring break / reverse / chop / stop / varispeed needs a path
through `internal/tape` that does **not** go through the undo stack — see
*Momentary gestures must not touch undo* in `AGENTS.md`. The existing
track-mute PATCH is undoable, so reusing it would leave tens of undo entries
behind after one jam.

That is Go, and the sandbox this was built in cannot download Go modules. So
it was deliberately not attempted there. A laptop with a working toolchain is
the right place: write it, `go test -race ./...`, then merge.

Worth writing the spec first, as everything else here was.

## Open decisions (nobody has picked these)

1. **Where the auto-install trigger lives.** Gabe does not want to pull each
   release by hand. `POST /api/update` already does the install; what is
   missing is something that calls it when a release appears. Three options:
   the Pi polls and self-installs (an auto-update setting; cleanest, no
   inbound access, but Go); **the hub does it** (already on the cluster,
   already talks to the Pis, already knows about releases — the suggested
   pick); or GitHub Actions calls the Pi (needs Tailscale and a secret in CI,
   most moving parts).
2. **Where the Play mode switch belongs.** It is in Settings → *This device*,
   and Settings exists only on Capture — so a tape-page feature's switch
   lives on another page. Either put the settings sheet on the tape page too,
   or give Play mode its own toggle where it runs.
3. **Whether root `*.md` should stop cutting releases.** `AGENTS.md` is a
   root file, so editing it releases. The ignore list covers
   `docs/superpowers/**`, `docs/images/**`, `design/**` and `.github/**`, not
   root files. A one-line change to `release.yml` if the empty releases annoy.

Decisions already taken today, for the record: trick pads before crate launch
pads; Play mode as a full-screen overlay on the tape page rather than a
fourth tab; the object library before Play mode so its objects are born in it.

## Two mistakes worth not repeating

- A module moved one directory deeper kept its old relative imports and
  nothing failed until a browser showed a blank page. `paths.test.js` exists
  because of it; it now also checks that every test directory appears in
  CI's globs, after a whole suite turned out never to have run.
- A new CSS rule for one sheet used a class that was already in use, and
  reached everything else using it. Scope the selector.
