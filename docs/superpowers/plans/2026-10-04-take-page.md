# One take page — step 3 of the editing-model roadmap

**Spec:** [editing model](../specs/2026-10-03-editing-model-design.md):
"One set of gestures", "Parity and consistency", "Words", "Help, tooltips and
the guide". **Checks:** [guide](../../guide.md), the "step 3" lists.
**Branch:** `take-page`, stacked on `phone-recording`.

The biggest UI change on the roadmap. The take page becomes the one place a
take is edited, with the gesture zones, toolbar and words the tape page will
reuse.

## Decisions taken while planning

- **One scale everywhere: dB.** The list already draws peaks on the dB scale
  the meters and the ribbon use; the take page and the overview move to it,
  through one renderer (`lib/wave/draw.js`). A quiet take then reads the same
  on every screen, and the *fit quiet takes* checkbox goes: it existed to
  rescue linear drawing.
- **WaveSurfer goes.** List rows draw with the shared renderer and play
  through a plain `<audio>`; the vendored copy is removed. That's what makes
  "one renderer" literal.
- **Loop is off on every open.** Decision 1 says off by default; it isn't
  remembered between takes.
- **Snap** is a chip that cycles *off · bar · beat · ⅛*, shown only with a
  BPM, remembered per device, off by default. It applies to taps that move
  the playhead, grip drags, hold-selects, In/Out and the nudges.
- **In and Out** work like the OP-1's loop points: In sets the start at the
  playhead and Out the end. With no selection yet, the first one is held as a
  pending point (drawn as a marker) until the other completes it, in either
  order.
- **Header:** back · ◂ · name (tap to rename) · ★ · ▸ · **?** · **⋯**. A
  second line carries the BPM (tap to set), the length ("1:12 of 7:00" with a
  selection) and, for a cut, "from *source*" linking to it. **⋯** holds
  *reset downbeat* and *the guide*.
- **Toolbar**, in rows that fit 320 px:
  - transport: ▶ · ⟲ Loop · In · Out · ⚑ · ◂⚑ · ⚑▸;
  - selection (only with one): In time ◂ ▸ · length · Out time ◂ ▸ · Clear;
  - verbs: Save as take · Share · More (DAW bundle, WAV, MIDI, delete);
  - footer: the position readout, Snap, and Practice speed (½× 1× 2×,
    disabled while Loop is on).
- **Prev/next take** use the list order the main page last showed (kept in
  `sessionStorage`), fetched from `/api/jams` when there is none.
- **The guide page** is `/guide.html`, rendering `/guide.md` with a small
  vanilla renderer. The server serves the guide compiled in (`docs/embed.go`),
  so it works from a checkout and from a release without copying files.
- **"Waiting for the interface"** is a typed state: the capture source wraps
  its no-device error in `audio.ErrNoDevice`, `/api/status` reports
  `capture_waiting`, and the main page shows an amber dot with that wording
  and no error toast.

## Tasks

1. **Gesture zones** (`lib/edit/gestures.js`, `lib/wave/view.js`). The pointer
   machinery -- pan, hold to select, double-tap, pinch, edge scroll, cancel
   and rollback -- moves into a `GestureSurface` base class the view extends,
   so the tape page can extend it too. The view gains the ruler (pins on top,
   bars and the playhead handle below) and the grip strip (In, Out, move
   handle), and a drag in the body always pans.
2. **Snap, In/Out and pending points** (`geometry.js`): `snapFrame`, the In/Out
   rules, flag stepping. Node-tested.
3. **Loop toggle and practice speed** (`page.js`, `clock.js`).
4. **The header and toolbar** (`wave.html`, `page.js`, `styles.css`),
   including rename, star, BPM, lineage, prev/next, More and ⋯.
5. **One renderer** (`lib/wave/draw.js`) for list rows, the overview and the
   take page; list rows without WaveSurfer, with the selection bracket and
   "1:12 of 7:00".
6. **Back returns to the list where you left it; wake lock while playing.**
7. **Lanes and notes:** a lane header menu (collapse, drums/notes, hide)
   instead of the hold; notes chips say *hide*; the phone's notes view keeps
   a waveform strip.
8. **The main page:** version shown; *waiting for the interface*; *Flag now*.
9. **Help:** `lib/help/tips.js`, `data-tip` on every control, `title` on a
   computer, the **?** help mode, three first-run hints per page, the guide
   page, and a node test that the tips, the HTML and the guide's table agree.
10. **Words** everywhere: selection, Save as take, Share, Clear, Practice
    speed, Flag now.
11. **Docs:** guide §4 and step-3 checks, architecture, README.
