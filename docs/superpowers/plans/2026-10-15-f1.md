# F1 · Two verbs — implementation plan

**Goal:** A selection of the feed offers **GRAB** and **KEEP**; every KEEP
names what it keeps; GRAB starts at the loop's length; a take's TO THE STUDIO
and Send to → Tape / → Clipboard become GRAB.

**Spec:** `docs/superpowers/specs/2026-10-15-flow-design.md` — *The Studio: one
selection, two verbs*, the verbs table, both words tables, decisions 9 and 12,
and *Build order* F1. Changes the code of P2 (the buffer, the ribbon) and P5
(`lib/room/notes.js`, the chair, the doorway's sheet).

**Branch:** `rooms/flow-f1`, PR base `rooms/all`. Nothing merged to `main`.

## Global Constraints

- Behind `hindsight.rooms` (and `hindsight.play` for the pad). With the rooms
  off, Capture (`index.html`), the take page and the old words are untouched.
- No server change: GRAB reuses `POST /api/clipboard` (`{take, from, to, grab}`
  for a take; `{ring_from, ring_to}` for the feed), as P2 already sends it.
- The crate stays (F3 removes it): only the selection stops offering
  *Keep as clip*. *Send to → Crate* and *Split here* stay.
- Every new test is seen failing first (reverted code, or the module absent);
  the commit says so.
- `sw.js` → `hindsight-shell-v99`; new `lib/` files go in `SHELL`.
- A KEEP's label fits 390 px.

## Decisions the spec left open

- **The picker's start.** The loop's bars when the loop is on, else the
  tape's first loop (`grid.bars`); then the largest of 1 / 2 / 4 / 8 that
  does not exceed it (3 → 2, 6 → 4, 16 → 8), so a grab fits inside the loop
  it is for (DROP still refuses a part longer than the loop until F7). Picked
  by hand, it stays until the loop's length changes. With no tempo or no tape
  the old saved pick (`buffer.bars`, else 4) stands.
- **A take's GRAB with the playhead at 0** (nothing before it): the first N
  bars, rather than an empty span.
- **A take's N** is the same number as the feed's would start at (loop's bars,
  else the saved pick, else 4); the take side has no picker until F6.
