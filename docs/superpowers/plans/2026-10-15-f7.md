# F7 · ● arms one, DROP never refuses, CATCH says what and why — implementation plan

**Goal:** With the rooms on, a tap on a track's ● moves the arm to that
track and a hold (or ⇧-click) adds it; DROP lands on the armed track at the
next bar line inside the loop, over what is there, and its key says so first
(*DROP ON TRACK 2 · bars 1–4 · replaces*); it is never refused for room; and
CATCH's key reads *last pass → 2* and *after one pass* while it waits, on the
phone's mini bar too. With the rooms off, nothing changes.

**Spec:** `docs/superpowers/specs/2026-10-15-flow-design.md` — *The Studio: one
selection, two verbs* (bullets *GRAB starts at the loop's length*, **DROP never
says *no room***, **● arms one; holding ● adds one**, **CATCH says what it
catches, and why it waits**), decisions 10 and 11, *Checks* (DROP's place;
arming), *Build order* F7. Changes the code of P6 (`lib/rig/arm.js`) and P2
(`lib/buffer/model.js`, `buffer.js`).

## Decisions the spec left open

- **A tap on a ● moves the arm; it never disarms.** Tapping the only armed
  track's ● leaves it armed (the way to none is a hold on it). Tapping an
  armed track among several makes it the only one: that is "● 1 (track 4 lets
  go)". This is what keys 1–4 already do (`pick` -> `armTrack`).
- **A hold (or ⇧-click, or ⇧-Enter) toggles membership:** adds an unarmed
  track, takes an armed one off (so the last can be taken off, to none).
  Touch hold uses `HOLD_MS` from `lib/tape/clipgestures.js` (300 ms, the
  tape's own hold).
- **"Only track N" is retired.** A tap does exactly that, on the very ● that
  was just held. The toast that says *Catch and Rec record onto all of them,
  DROP onto the first* stays (it still tells the truth) and gains "Tap a ● to
  go back to one."
- **Labels name both gestures** ("Arm only track 3: … Hold to arm it as
  well"), and what they say Catch and Rec will use stays checked against the
  set the gesture makes (the existing label-vs-result test, for both).
- **No armed track: DROP is disabled** and says *arm a track* (it used to pick
  the first track with room). No "No room" any more.
- **Place:** the next bar line at or after the playhead inside the loop
  where the whole part fits before the loop's Out; none left -> the first bar
  line at or after the loop's In (wrapping), else the loop's In itself. The
  loop off: the tape (0 to its end), same rule. No tempo: the playhead, or 0
  on an empty tape. A part longer than the loop starts at the loop's In and
  runs past it; the toast says so. Only a part longer than the **tape** is
  refused (it cannot be laid), saying so.
- **The key:** `Drop on track 2` / `bars 1–4 · replaces` (`· replaces` exactly
  when `overwritten(...)` finds a clip under the span on the lanes it lands
  on). The old `, the next free span · ↵` tail goes (the key already has
  `aria-keyshortcuts="Enter"`); several armed -> still the first, with
  "the first armed track ·" before the bars.
- **CATCH:** the second line is `last pass → 2` / `→ 2, 3` (the armed tracks,
  no "track" word) and `after one pass` while it waits for one (the Studio
  only; the old `waits for a pass` stays for the old pages); `press ▶`,
  `loop is off`, `arm a track` stay. The phone's mini bar hides the second
  line today (`display: none`), so on a phone the words never showed. A
  rooms Catch gets a second, shorter line there (`catchMini`: `→ 2`,
  `in 1 pass`, `arm track`, nine characters at most), because the full line
  widened the key by 24 px and the transport window beside it lost its bar
  number ("1…" for "1.4", seen at 390 px); the short one costs 8 px and the
  number stays. The expanded player and the key's tip and label say it all.

## Review fixes (PR #125 review)

Each seen failing first (or, for the surviving-mutant ones, killed by mutation).

- [x] **The guide and the tip on a second ↵.** The page passes an explicit
  `at` and the playhead stays, so stopped, ↵ again lands in the same place and
  *replaces its own copy*; playing, the next bar line has moved on. Kept (the
  spec says the next bar line from the playhead); the guide and the
  `buffer-drop` tip now say so.
- [x] **"Replaces" follows the Pi's rule for picked clips.** `overwritten`,
  `landsWords` and `dropKey` take the `board`; with `board.clips` only the span
  under each copied clip counts (internal/tape `dropBoard`), the whole window
  otherwise. The reviewer's repro is a test, and a seeded property test checks
  `replaces` against the Pi's rule over 400 random tapes and boards (spans and
  picked clips, one and two lanes). The toast and the drag ghost use it too.
  A live fuzz against the demo (`f7/fuzz.mjs`, from the reviewer's) now copies
  several picked clips off the tape a third of the time.
- [x] **"Longer than the tape" only for a part longer than the tape.** A part
  that fits the tape but not from the loop's In (a loop near the tape's end)
  starts at the **latest bar line from which it fits** (the tape's end less the
  part with no tempo), the key and toast say *moved back to fit the tape*
  (`dropPlace` -> `fitted`). Chosen over "the tape's start" because it stays
  nearest the loop. `long` is now "ends past the loop's Out".
- [x] **`dropPlace`'s branches tested and mutation-killed.** Playhead before
  the loop, at and after its Out, 7.5 of 8 bars, a loop In off a bar line,
  the no-tempo loop. Two mutants survived at first: the `looping && frames >
  hi - lo` branch (redundant: the wrap already lands on the In, so it is
  removed) and the no-tempo "does it fit" test (a test added). `pos < hi` was
  an equivalent mutant (past the Out nothing fits ahead, so it wraps) and is
  now `Math.max(pos, lo)`.
- [x] **A hold is a finger's or a pen's.** `armPress` starts its timer only for
  `pointerType` touch or pen: a slow mouse click is a tap and a mouse adds with
  Shift-click. The keyboard path is unchanged.
- [x] **Keyboard users are told.** The ● labels say "Hold (Shift-click,
  Shift+Enter) to ...".
- [x] **Nits.** The shared ● tip says what is true of each mode; the guide's
  mini-bar words match the key (*→ 2*, *in 1 pass*); `catchMini` stays within
  nine characters for any set of armed tracks (`→ 1–4`, else `→ 5 trk`).
