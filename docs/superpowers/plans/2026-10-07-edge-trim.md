# Edge trim, with handles (A1) — implementation plan

**Goal:** Drag a picked clip's edge to trim it, with 2 s of handle in every
new pool file so a trimmed edge can grow back.

**Architecture:** A `TAPE_HANDLE_S` setting reaches the engine as
`Options.HandleSeconds`. Every pool writer takes up to that much either side.
A `trim` edit clamps an edge to the file, the layer's neighbours and the tape.
On the page, `clipgestures.js`'s grips go live for the picked clip, and
`geometry.js` mirrors the clamp for the drag's preview.

**Spec:** `docs/superpowers/specs/2026-10-07-edge-trim-design.md`

## Global Constraints

- Existing tests keep passing: an engine with no handle set keeps only the
  overhang.
- A catch never waits longer than it did for audio after its span.
- `peak_db` stays the clip's and its overhang's.
- One `trim` per drag; one undo.
- `sw.js` → `v38`; `TIPS` and guide §9 match.

## Review Focus

1. **The Out bound** keeps the overhang a crossfade out of the clip reads,
   unless the clip already runs into it.
2. **The ring's oldest edge**: handles keep a second clear of it, so a catch
   near the ring's end doesn't fail for want of a handle.
3. **A grip press and the lanes' pan**: `state.trim` is set on the press, so
   `wireView` lets go of it before it moves.
