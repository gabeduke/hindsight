# F3 · The buffer is the only view — implementation plan

**Goal:** With the rooms on, the Studio has no crate drawer and no clipboard
line, the take page has no *Split here*, no *Send to → Crate* and no ◫ chip,
a part has no *Keep*, and a GRAB over a buffer nobody dropped or kept says so
with **Undo**. The Pi keeps exactly one replaced grab for that Undo. With the
rooms off, nothing changes.

**Spec:** `docs/superpowers/specs/2026-10-15-flow-design.md` — the verbs table
(*Keep (the clipboard into the crate), a part's Keep*, *Send to ▾ → Crate,
Split here*), the things table (*clip (in the crate), crate, Find a clip, ◫*),
*The Studio: one selection, two verbs* (its last bullet), the Studio row of
*What changes, page by page*, decision 9, *Not in this* (the server), *Checks*
(Go: *one replaced grab is kept, and let go at the next*), and *Build order*
F3. Changes the code of P2 (`lib/buffer`), the tape page (under the flag) and
Go.

**Branch:** `rooms/flow-f3`, off `rooms/all` (F1, F2 and the cable tidy are in;
`CACHE` was v101). PR base `rooms/all`: retarget before merging; never merge
to `main`.

## Global Constraints

- Behind `hindsight.rooms`. With it off the tape page keeps its Crate drawer,
  the clipboard line, *Keep* on a part, *Keep as clip*; the take page keeps
  *Split here*, *Send to → Crate* and the ◫ chip; the Takes page keeps its ◫
  line; the Pi keeps putting a replaced unused grab in the crate. Word for
  word.
- **The crate leaves the screen, not the Pi** (decision 9). Every crate route
  (`/api/crate*`, `POST /api/tapes/drop {crate}`) and the crate's clips stay;
  nothing is converted or deleted.
- **This step changes Go.** A release of it needs a restart on the rig
  (`make deploy`), not just `make deploy-static`.
- Every new test is seen failing first (code absent, or the old code put
  back); the commit says so.
- `sw.js` → `hindsight-shell-v102`; new `lib/` files go in `SHELL`, deleted
  ones come out; a new `lib/` directory with tests goes in the node globs of
  `AGENTS.md` and `ci.yml` (none planned).
- New CSS is scoped to what it styles.

## Decisions the spec left open

- **The one replaced grab is a second file, additive.** `setBoardLocked`
  already notices "an unused grab is being replaced" and puts it in the crate.
  It now also writes it to `clipboard-replaced.json` (the buffer it was, and
  `By`: the `Created` of the buffer that replaced it), overwriting any older
  one, so only one is ever kept and each replacement lets go of the last. The
  crate keeps happening as before unless the request says `"crate": false`,
  which every rooms GRAB does, so a rooms Pi does not grow a crate nobody can
  see. Cut and Copy on the tape (`/api/tapes/edit`) still crate what they
  replace (they have no request option to carry it): the slot is written for
  them too, but the Studio offers no Undo for them in this step.
- **Undo is a restore, not a swap.**
  `POST /api/clipboard/restore?replaced=1` puts the replaced buffer back on the
  clipboard and empties the slot; the grab it undoes is thrown away (its pool
  files are the clean-up's, unreferenced). It refuses (409, *nothing to put
  back*) when the buffer on the clipboard is no longer the one that replaced
  it: cleared, tossed, or replaced again. A second Undo has nothing to do. It
  is the existing `restore` route with an option, the way `DELETE ?toss=1`
  is the existing clear with one: no new route.
- **Who says "replaced".** The answer to a GRAB carries `replaced` (the old
  buffer) and `replaced_seconds` when it replaced an unused grab, so the
  toast reads the Pi's truth, not what this page last saw. A take's GRAB
  navigates to the Studio at once, so it leaves the notice in `sessionStorage`
  for the Studio's buffer to raise once, for that buffer only.
- **Cut and Copy have no view.** The buffer panel shows grabs (it needs a
  window to trim); a range's Cut/Copy still lands on the clipboard and its
  toast says so, and *Paste*/*Insert* on the range bar use it. Showing a
  non-grab clipboard in the buffer is not built here; F7 reworks DROP.
- **The empty tape's hint** says *Or GRAB a bit of a take: open one, select the
  part and press GRAB.* with the rooms on.

## Review fixes

- [x] **Range Cut/Copy and the toss's Undo leave the crate alone.**
  `POST /api/tapes/edit` takes `no_crate` (not `crate`, an insert's), `POST
  /api/clipboard/restore` takes `?crate=0`; the rooms send them and say what
  was replaced, with Undo (`edit.replaced`, `replaced`). The hidden crate does
  not grow under rooms use. Copies made by `POST /api/clipboard` with a take
  or the ring (no rooms screen offers them) still crate, as before.
- [x] **The slot holds any unused buffer**, a copy or cut as well as a grab
  (`Clipboard.Used` is set when a copy is dropped, inserted or kept, as
  `Grab.Used` is for a grab). Only a *grab* is also put in the crate when the
  crate is kept, as it always was.
- [x] **The slot is let go.** `Cleanup` roots it only while it is live (the
  buffer that replaced it is still the clipboard and unused); Clear and Toss
  remove it at once. A toss ends a slot's life for good: bringing the tossed
  buffer back does not revive the older Undo (simplest; said in the guide). A
  tape switch changes nothing, since the clipboard is shared by every tape.
  Dropped, inserted and kept leave the file (so the Undo can say *Already
  dropped or kept*) but it roots nothing.
- [x] **Undo after a DROP is refused** (409, *Already dropped or kept — undo
  the drop instead*), as is an older grab's Undo (*That grab was already
  replaced*); the toast shows the Pi's words as they are, and a newer Undo
  takes the older one off the screen.
- [x] **A failed write keeps the Undo that was there:** the slot is written
  first, then the crate and the clipboard, and put back as it was if either
  fails (tested with a crate that cannot be written).
- [x] **Small:** `replaced=` is 1 or 400; the take's GRAB note is good for a
  minute and let go by the Takes page and the take page; `ClearClipboard` takes
  the buffer's lock (nothing that holds it calls it).
