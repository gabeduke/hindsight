# The rig (P6) — implementation plan

**Goal:** Draw the kit as devices and cables that *are* its settings, so
input routing can be seen and changed in one place; and let two taps record
onto two tracks at once (multi-arm).

**Spec:** `docs/superpowers/specs/2026-10-15-rig-design.md` (the measurements
behind the Sidekick's profile: `docs/sidekick-routing.md`)

## Global Constraints

- Behind `hindsight.rooms`, this device only. With it off nothing changes:
  no device chip, no rig link, no amber dot, ● arms one track as today.
- The server owns the graph: `GET /api/rig` derives it every read from the
  settings, the tape and what's plugged in. The page draws and never stores.
- Backward compatible: `rec_track` is still answered (the first armed
  track) and a PATCH of it still arms just that one; old `tape.json` files
  (with `rec_track` only, or none) load; the old `{track, source}` bodies of
  catch, record and tap still work.
- Every recording path records every armed track from its own input over
  one span as **one undo**: catch (a pass, the last N bars), ● Rec and a
  punch, a free loop's taps.
- The rig never restarts on its own; a restart cable is pending (dashed
  amber) until the Pi restarts, from each key's saved value against its
  running one; RESTART is the settings sheet's own, with its warning.
- Profiles are embedded JSON matched by USB id (ALSA's `usbid`) or MIDI
  name; nothing is guessed: unknown cards get a generic profile, the
  Bento's is a placeholder with no audio ports.
- Cable kinds differ by width and dash, not colour alone. Every socket is
  a button; the cables are drawn over them and take no input.
- CSS in one block at the end of `styles.css` (*Rooms P6*), every selector
  on a `rig-` class (or the Studio's `.tt-warn`).
- `sw.js` → `v83`; every new file in `SHELL`; `lib/rig/` in the
  `node --test` globs of `AGENTS.md` and `ci.yml`.

---

- [ ] **Multi-arm, the model (tests first):** `Tape.RecTracks []int`
  (`rec_tracks`), sorted, with `RecTrack` kept in step as the first armed
  (`NoRecTrack` for none) so `rec_track` still reads; `normalizeArm` on
  load: `rec_track` alone → `[n]`, absent → `[1]`, `-1` → `[]`. `Clone`
  keeps both. PATCH `{rec_tracks: [...]}` sets the set; `{rec_track: n}`
  arms just that one. A tape.json written by today's code loads.
- [ ] **Multi-arm, recording (tests first):** `Pair{Track, Source}`;
  `CatchRequest.Pairs`; `catchSpan` writes one pool file per source and
  places every track in one `Edit`. `Record` and `Tap` take pairs too;
  `Recording.Pairs`, `Kept.Tracks`, `Kept.Clips`. Catch answers `clips`
  and `tracks`. Old single bodies unchanged.
- [ ] **`internal/rig`:** `profiles/ep-136.json` (from
  `sidekick-routing.md`; its taps are today's default `TAPE_SOURCES`),
  `profiles/bento.json` (placeholder: MIDI by name, no audio ports),
  `Generic(channels)`; `MatchUSB`, `MatchMIDI`; ALSA `usbid` for a card from
  the capture's `(hw:N,…)` name; `Build(Inputs)` → the graph: devices,
  the kit's sockets (taps, track inputs, buses, OUT, clock in/out, KEEP),
  cables with kind/writes/pending, warnings with their fix, labels.
- [ ] **Warnings, worked out:** a tap that hears a bus, patched to an armed
  track, while an unmuted track with clips plays on that bus: the tracks,
  and the fix (*Move tracks 1, 4 to bus B*) when there's a bus no armed
  tap hears. PATCH `{buses: [{n, bus}]}` moves several as one undo.
- [ ] **API:** `GET /api/rig`, `PUT /api/rig/labels` (`rig.json` beside
  `settings.json`, never routes anything). The demo reports the Sidekick's
  USB id (its routing is the Sidekick's), so the demo's rig is the
  Sidekick. `TAPE_CONTROLLER`'s cable only if the registry has it (P3).
- [ ] **Go checks** (spec *Checks*): taps = `TAPE_SOURCES`; generic
  profile; each cable's write shows on the next read, a restart cable
  pending; the warning appears and clears; multi-arm catch, passes, punch,
  taps; `rec_track` reads and writes; old tape.json.
- [ ] **`lib/rig/`:** the graph from the JSON alone, a drag or a keyboard
  choice → the request it writes, unplugging, positions and cable paths
  (pure), width and dash per kind, multi-arm on the page (the set, pairs,
  *last 4 bars → 2, 3*), the device chip, the rig page, the Studio's amber
  dot. Tests beside each.
- [ ] **`rig.html`:** the desk, the patch bay, the inspector (a sheet on a
  phone), the legend, RESTART with the ring warning. `SHELL`,
  `pages.test.js`, `materials.test.js`.
- [ ] **The device chip:** in both rooms' headers, with the flag on only

- [ ] **The Studio:** ● toggles a track in the armed set (flag on); 1–4 and

  *last 4 bars → 2, 3*; the amber dot on a track header that records the

- [ ] **RESTART:** `settings.js` exports the sheet's restart, so the rig's

- [ ] **CSS:** the *Rooms P6* block.
