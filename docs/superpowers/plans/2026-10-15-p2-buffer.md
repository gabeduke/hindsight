# The Studio's buffer (P2) — implementation plan

**Goal:** One gesture from the feed to the tape: GRAB the last N bars (or a
span of the feed, from several sources) into a buffer between the feed and
the lanes, trim it there, then DROP it on a lane, KEEP it as a take, or TOSS
it.

**Spec:** `docs/superpowers/specs/2026-10-15-studio-buffer-design.md`

## Global Constraints

- **The buffer is the clipboard.** No second store: a grab is a clipboard
  with a `grab` record on it (its sources, its span on the ring, its handles
  and its window). It survives a reload and is the same on every device.
- Behind `hindsight.rooms` (P1's `lib/rooms/flag.js`), this device only. With
  it off: no markup (the buffer's markup is `<template>`s), no listeners, no
  requests; the clipboard, the crate and the tape page behave as today.
- Server routes and request fields are additive: `POST /api/clipboard`'s
  `{ring_from, ring_to, source}` and `{take, from, to}` answer as before, and
  plain `DELETE /api/clipboard` still just clears it.
- GRAB by bars is Catch's arithmetic, shared, not copied: `lastBars`, then
  the same output-to-ring mapping (`Δ` and `TAPE_LATENCY_MS`) as `catchSpan`.
- One undo per DROP (a clipboard drop already is). Nothing in the buffer
  touches undo until it lands.
- AUDITION plays on this device only, never through the Pi.
- CSS in one block at the end of `styles.css`, *Rooms P2*, every selector on a
  `buffer-` class; a test holds it there.
- The buffer's keys are their own small table (`lib/buffer/keys.js`) for P3
  to fold into its `controls.js`; never while typing, under a sheet or under
  Play mode.
- `sw.js` → `v79`; every new `lib/` file in `SHELL`; `lib/buffer/` in the
  `node --test` globs of `AGENTS.md` and `ci.yml`.
